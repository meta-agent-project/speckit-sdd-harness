# tdd

모든 기능은 테스트가 먼저다. 실패하는 테스트를 보지 않은 구현 코드는 쓰지 않는다.

flow가 단계에 맞는 모드(A·B·C·D)를 지정해 부른다. 지정 없이 부르면 A → C → D 순서로 한다.

대상 폴더는 `.specify/feature.json`의 `feature_directory`. 테스트 실행 명령과 화면이 있으면 **화면 측정 명령**은 그 영역 `plan.md`의 기술 맥락에 적힌 것을 쓴다. 없으면 plan에 적게 하고 멈춘다.

## A. tasks 검사 (flow 4단계)
`spec.md`와 `tasks.md`를 대조한다.

1. 사용자 스토리마다 `### 사용자 스토리 N 테스트 (Tests for User Story N)` 묶음이 그 스토리의 구현 작업보다 **앞**에 있다.
2. 인수 시나리오마다 그것을 확인하는 테스트 작업이 하나 이상 있고, 작업 설명에 출처를 적는다(예: `US1-시나리오3`).
3. 구현이 필요한 SC(성능·안정성·복구 등)마다 테스트 작업이 있다(예: `SC-003`). 출시 뒤에만 잴 수 있는 지표는 뺀다.
4. 경계 사례도 테스트 작업에 들어간다.
5. 각 테스트 작업 설명에 "먼저 작성하고 실패 확인"이 드러난다.
6. 화면을 만들거나 바꾸는 영역이면: 바뀌는 화면 패턴의 **자리 표 관계**마다 화면 측정 작업이 있고(D), 그 작업의 견본 데이터에 빈 상태 · 많은 항목 · 가장 긴 실제 내용이 들어 있다. 화면 요소는 용도 부품으로 그리는지 확인하는 작업이 있다(화면 코드가 용도 부품을 쓰는지).

빠진 것이 있으면 `tasks.md`에 테스트 작업을 넣고 작업 ID를 처음부터 다시 매긴다(`T001`부터 순서대로, 체크 표시는 유지). 무엇을 더했는지 표로 보고한다: 출처 · 더한 작업.

그려진 화면의 자리 · 크기 · 정렬은 D(화면 측정)로 자동 확인한다. 사람만 정할 수 있는 것(취향 · 방향 결정)만 `사용자 확인:` 작업으로 두고, 그 전에 Claude가 캡처를 보고 고친 상태로 보인다.

## B. 구현 규칙 (flow 5단계)
`/speckit-implement`가 작업을 처리하는 동안 지킨다.

1. 테스트 작업: 테스트를 쓰고 **실행해서 실패를 확인**한다. 실패 이유가 "기능이 아직 없음"이어야 한다(문법 오류·잘못된 import로 실패하면 고친 뒤 다시). 실패 출력 요지를 작업 옆에 한 줄 남긴 뒤 체크한다.
2. 구현 작업: 그 테스트를 통과시키는 최소 코드만 쓴다. 테스트를 실행해 **통과를 확인**한 뒤 체크한다.
3. 실패 테스트 없이 구현 코드부터 쓰지 않는다. 이미 써 버렸으면 지우고 테스트부터 다시 한다.
4. 테스트를 통과시키려고 테스트를 고치지 않는다. 테스트가 틀렸으면 spec과 대조해 근거를 사용자에게 보고하고 정한다.
5. 한 사용자 스토리를 마치면 지금까지의 전체 테스트를 한 번 돌린다.

## C. 전체 실행 (flow 6단계)
1. plan의 테스트 명령으로 전체 테스트를 실제로 실행한다.
2. 결과를 표로 보고한다: 전체 · 통과 · 실패 · 건너뜀, 실패한 테스트 이름.
3. 실패나 건너뜀이 하나라도 있으면 **다음 단계로 가지 않는다.** flow 5단계로 돌아간다.
4. 모두 통과하면 화면이 있는 영역은 D로, 없는 영역은 flow 7단계(converge)로 간다.

## D. 화면 측정 · 캡처 자가 점검 (flow 6단계, 화면이 있는 영역)
그려진 화면이 디자인 스펙대로인지 실제 브라우저에서 확인한다. 소스 값 검사(C)는 각 부품이 토큰을 쓰는지 보고, D는 **조립된 화면**(같은 용도는 같은 크기, 담는 쪽 여백, 한 줄 높이, 긴 내용일 때 모습)을 본다.

1. plan의 화면 측정 명령으로 앱 화면을 화면 기준 크기로 띄운다. 견본 데이터는 빈 상태 · 많은 항목 · 가장 긴 실제 내용을 담는다.
2. 바뀐 화면 패턴과 같은 용도를 쓰는 화면마다 `specs/design-system.md` 자리 표의 관계를 잰다(요소 위치 · 크기 비교). 관계 하나가 테스트 하나다.
3. 화면 · 상태마다 캡처를 저장하고 **직접 열어 본다**. 같은 용도를 쓰는 화면끼리 나란히 놓고 본다. 어색한 곳(자리 · 여백 · 줄 높이 · 넘침)을 찾으면 자리 표에 그 관계를 더하고(스펙 먼저) 측정 테스트를 더해 실패를 본 뒤 고친다.
4. 결과를 표로 보고한다: 화면 · 관계 · 잰 값 · 기준 · 통과, 그리고 캡처 위치.
5. 모두 통과하고 캡처 점검에서 고칠 것이 없을 때 flow 7단계로 간다. 하나라도 남으면 flow 5단계로 돌아간다.

## 결과 보고
- 테스트 · 측정 결과는 실제로 실행한 출력으로 보고한다.
