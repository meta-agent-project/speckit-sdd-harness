# mockup

화면이 있는 모든 영역은 plan 전에 시안을 골라야 한다. 시안은 고르기 위한 도구이고, 남는 것은 `specs/design-system.md`의 값이다.

## 0. 대상과 건너뛰기
- 대상 폴더는 `.specify/feature.json`의 `feature_directory`.
- 그 `spec.md`에 `## 화면` 절이 없으면 "화면 없음 — 시안 건너뜀"이라고 알리고 끝낸다.
- `specs/design-system.md`의 "승인 기록"에 이 영역 행이 있고 그 뒤 `## 화면`이 바뀌지 않았으면 건너뛴다.

## 1. 읽기
- 그 영역 `spec.md`의 `## 화면`, 사용자 스토리, 경계 사례(빈 상태·오류·손상 같은 상태를 시안에 넣기 위해)
- `specs/design-system.md`

## 2. 시안 3개 만들기
- 위치: 저장소 밖 임시 폴더(세션 scratchpad, 없으면 `%TEMP%\mockups\<영역 폴더>\`). 저장소에 두지 않는다.
- 파일: `a.html` · `b.html` · `c.html` · 비교용 `index.html`.
- 각 시안은 외부 의존 없는 단일 HTML. 화면 크기는 constitution·spec이 말하는 대상 기기 기준(없으면 1280×800).
- 모든 디자인 값은 `:root`의 CSS 변수(`--color-…`, `--font-…`, `--space-…`, `--radius-…`)로만 쓴다. 승인 뒤 그대로 `specs/design-system.md` 토큰이 된다.
- 내용은 spec에서 가져온 실제 한국어(실제 쓰일 법한 데이터). lorem ipsum 금지.
- `## 화면`의 모든 화면과 spec의 상태(빈 목록, 오류 알림, 손상 표시, 저장 중 등)를 보여 준다. 상태는 한 페이지 안에 나란히 두거나 상단 전환 버튼으로 바꿔 본다.
- 세 시안은 **확실히 다른 방향**이어야 한다(배치·밀도·색 분위기·글꼴 중 둘 이상이 다름). 색만 바꾼 변형은 안 된다.
  - `design-system.md`에 토큰이 아직 없으면: 전체 시각 방향을 셋으로 나눈다.
  - 토큰이 이미 있으면: 기존 토큰·부품은 그대로 쓰고, 이 영역 화면의 배치·구성만 셋으로 나눈다. 새 부품이 필요할 때만 새 모양을 제안한다.
- `index.html`: A·B·C를 iframe으로 나란히(또는 탭으로) 보여 주고, 시안마다 방향을 한 줄로 설명한다.

## 3. 고르기
- `index.html`을 브라우저로 연다(PowerShell `Start-Process <경로>`).
- AskUserQuestion으로 A · B · C 중 하나와 고칠 점을 받는다. 섞고 싶다는 답(예: "A 배치 + C 색")도 받는다.
- 고칠 점이 있으면 고른 시안 하나만 고쳐 다시 보여 준다. 사용자가 승인할 때까지 반복한다.

## 4. design-system.md에 옮기기
승인된 시안에서:
- `## 토큰`: CSS 변수 이름과 값, 용도 한 줄.
- `## 부품`: 이 화면에서 쓴 부품마다 이름 · 쓰임 · 모양·상태(기본/눌림/비활성/오류 등) · 처음 쓴 영역.
- `## 화면 패턴`: 화면 배치 규칙(예: "목록 화면: 위 제목줄 + 아래 목록, 빈 상태 안내 가운데").
- `## 승인 기록`: 영역 · 날짜 · 고른 시안과 방향 한 줄 · 반영한 고칠 점. flow가 2단계 완료를 이 행으로 판정한다.
- 기존 값과 다르게 바꿔야 하면 사용자에게 먼저 묻는다. 바꾸면 그 값을 쓰는 다른 영역 화면에도 영향이 있다는 것을 알린다.
- 시안 파일 경로를 대화에 한 줄 남기고 끝낸다. 시안 파일은 커밋하지 않는다.

## 하지 않는 것
- 이미지 생성 API로 시안을 만들지 않는다. HTML로만 만든다.
- spec에 디자인 값을 쓰지 않는다.
- 사용자 승인 없이 `design-system.md`를 바꾸지 않는다.
