# 생성형 그림 화풍 명세

## 목표

승인한 두 견본을 few-shot으로 전달해 강의·책의 설명 그림을 일관되게 만든다. 흰 바탕과 검정 펜·회색 명암이 중심이고 여러 강조색은 구조 구분을 돕는다. 구도와 비유는 설명할 내용에 맞게 선택한다.

## 요구사항

- 원본 PNG 두 장은 스킬에 함께 보관한다. 구조 설명 견본이 첫 번째, 장면 설명 견본이 두 번째다. 새 그림·수정·자동 재시도에서도 같은 두 장을 실제 생성 도구에 전달한다.
- 강조색 개수를 1~2개로 제한하지 않는다. 색 테두리·이름표·연결선과 이름표의 옅은 채움을 허용하고, 넓은 컬러 배경·사물 전체의 다색 채움·강한 그라데이션·발광 효과는 피한다.
- 카페·커피·손·조립 장면과 견본의 글자를 원고와 무관하게 반복하지 않는다. 설명에 필요한 같은 소재는 사용할 수 있다.
- 원고의 관계·방향·수치·용어·이름표 철자를 유지한다. 가독성과 충분한 여백을 확보한다.
- 검색한 참고는 세 번째 내용 자료다. 검색 그림의 색이나 화풍을 따라가지 않는다.
- 검수는 실제 결과 PNG의 핵심 정확성·가독성을 통과 기준으로 보고 화풍·색·장식 취향은 경고로 분리한다. 앱 검수에는 결과 PNG 한 장과 현재 화풍 지침을 보내며, 견본까지 세 장을 보내 LLM 첨부 한도를 넘기지 않는다.
- 핵심 오류로 미통과하면 준비한 요청에 구체적인 사유를 더하고 동일한 두 견본으로 한 번 자동 재생성한다. 별도 요청 쓰기 호출은 하지 않는다. 마지막 미통과는 그대로 알린다. 검수한 원본 PNG의 색·배경·투명도를 후처리로 바꾸지 않는다.

## 앱 하네스 등록

- 항목: `skill.figure-style` / 생성형 그림 화풍 / 스킬.
- 적용 단계: 그림 요청·그림 생성·그림 검수. 일반 원고 집필·실제 화면 캡처·시뮬레이터에는 추가하지 않는다.
- 앱에서 1,500자 이내 수정·자동 저장·기본값 복원을 지원한다. 이미지 생성 요청에 원고 내용과 참고 역할도 들어가므로 화풍 지침의 편집 길이에 여유를 둔다. 비운 항목은 승인한 기본 화풍을 사용한다.
- 같은 작업은 시작 시 읽은 지침을 유지한다. 수정한 지침은 다음 생성·다시 만들기부터 적용하고 기존 이미지는 자동 교체하지 않는다.

## 인수 기준

구조·비유·관계도 세 유형 모두 흑백 그림 중심으로 생성되며 구분을 돕는 여러 강조색이 허용된다. 작성과 생성의 실제 첨부, 검색 참고의 순서, 재시도·다시 만들기, 하네스 수정·복원·작업 시작 시 지침 보존을 확인한다. 자동 테스트와 별도로 실제 PNG를 열어 화풍과 가독성을 확인한다.

## 준비·복구·실행 예시 계약

- 단일 출력 정상 경로는 준비1·생성1·점검1. 준비는 장 수·부분·순서·최종 요청을 함께 반환한다. 명시적 찾기만 검색하며 애매한 도구화면 분류는 필요할 때 별도 호출로 기록한다.
- 외부 준비 입력 전체의 지문이 같을 때만 캐시한다. 원고 앞뒤 글·이름표·사용자 고칠 점·화풍·지정 장·참고 변경을 놓치지 않는다. 지난 생성 요청/점검은 새 준비 때 제공하는 내부 결과로서 캐시 무효화 입력이 아니다. 같은 외부 입력의 다시 만들기는 생성1·점검1로 준비를 재사용할 수 있다.
- 이미지 생성 직후 원본과 pending을 저장한다. 점검 상태는 passed·needsCorrection·unavailable이며 warning-only는 passed다. timeout·전송·잘못된 답은 unavailable로 저장하고 배치를 계속한다. checker만 idle90/total180이며 다른 작업 제한은 유지한다.
- 점검만 재시도는 준비·검색·생성0회다. 재시작 뒤 원본 PNG·준비·pending을 포함한 이미지별 점검을 그대로 읽고 확인 전에서 점검만 재시도를 제공하며 기존 check 종합 필드·옛 그림을 호환한다.
- 실행 결과는 같은 화풍의 생성형 예시가 기본이며 실제 실행 안 함을 표시한다. 코드·설치·DB·서버를 실행하지 않는다. 도구·설정 화면은 skipped, 수동 사진은 이미지 변경으로 넣고 보존한다.
