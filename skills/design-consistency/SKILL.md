# design-consistency

원칙: 디자인도 스펙이 먼저다. 이 스킬은 **스펙을** 바꾼다. 코드는 읽고 화면은 캡처해 재며, 바뀐 스펙에 코드를 맞추는 일은 backlog → 영역 작업(tasks → TDD → 화면 측정 → converge)이 한다.

## 디자인은 용도로 조립한다

화면의 모든 요소는 **용도 하나**에 속한다(예: 네비게이션 패널 · 검색 · 수정 · 화면 주요 동작 · 줄 안 동작 · 묶음 이름 · 상태 표시). 용도 하나는 부품 · 변형 · 토큰 하나로 그린다. 화면은 자리마다 용도를 놓아 조립한다. 그래서 같은 용도는 어느 화면에서나 처음부터 같은 모양 · 같은 크기다.

조립 규칙:
- **같은 용도 = 같은 부품.** 두 화면에 같은 일을 하는 자리가 있으면 같은 용도 하나를 쓴다.
- **여백은 담는 쪽이 정한다.** 부품은 안쪽 여백만 갖는다. 부품 사이 · 둘레 여백은 담는 용도(패널 · 줄 · 본문 틀)가 정한다. 그래서 첫 줄 위치는 담는 쪽 하나로 정해진다.
- **한 줄은 높이 하나.** 줄 용도(거르기 줄 · 동작 줄 · 막대)가 높이를 갖고, 그 줄의 조작 요소(버튼 · 입력칸 · 묶음)는 줄 높이를 따른다.
- **내용이 늘면 정한 대로 자란다.** 용도마다 긴 내용일 때의 모습(말줄임 · 줄바꿈 · 첫 줄 맞춤)을 정해 둔다.

## 디자인 스펙 네 층
값은 한 곳에만 둔다. 아래 층은 위 층의 **이름만** 쓴다.

| 층 | 파일 | 담는 것 |
|---|---|---|
| 1 토큰 | `specs/design/tokens.md` | 값. 기본 토큰(색 · 글자 · 굵기 · 여백 · 모서리 · 선 · 높이 · 폭)과 의미 토큰(쓰임 이름 → 기본 토큰) |
| 2 부품 | `specs/design/components.md` | 모양. 부품마다 같은 형식(아래). 토큰 이름만(부품 안에서만 쓰는 크기는 `고정 <값>`) |
| 3 용도 | `specs/design/roles.md` | 용도마다: 하는 일 · 부품과 변형 · 크기(높이 · 폭 토큰) · 담을 때 여백 · 긴 내용일 때 · 쓰는 화면 |
| 4 디자인 시스템 | `specs/design-system.md` | 공통 레이아웃 · 화면 패턴(자리마다 용도 이름) · **자리 표**(화면 패턴마다 잴 관계) · 승인 기록 |

부품 정의 형식:
```
### 버튼 (Button)
- 쓰임: 동작 하나
- 크기: 높이는 용도가 정함 · 안쪽 0 --space-4
- 글자: --font-size-sm / --font-weight-regular
- 색: 바탕 --color-surface · 글자 --color-text · 테두리 --border-strong
- 모서리: --radius-btn
- 상태: 기본 · hover(바탕 --color-soft) · 비활성(글자 --color-faint)
- 변형: 기본 · 주요 · 텍스트
- 처음 쓴 영역: 001
```

용도 정의 형식:
```
### 네비게이션 패널 (Nav Panel)
- 하는 일: 화면 왼쪽에서 볼 범위 · 항목을 고른다
- 부품: 패널 + 목록 줄 + 캡션
- 크기: 폭 --panel-w · 안쪽 --space-5 --space-3 --space-4
- 담을 때: 첫 줄은 패널 안쪽 위에서 시작(줄 자체 위 여백 0) · 줄 사이 --space-1
- 긴 내용일 때: 이름 한 줄 말줄임, 전체 이름은 마우스를 올리면 · 상태 표시는 첫 줄에 맞춤
- 쓰는 화면: 라이브러리 · 작업 · 고르기 창
```

자리 표(디자인 시스템 안) 형식 — 그려진 화면에서 재서 확인할 관계:
```
| 화면 패턴 | 관계 | 기준 |
| 왼쪽 패널 | 왼쪽 단 오른쪽 끝 x = 화면 제목 시작 x | --panel-w |
| 왼쪽 패널 | 패널 첫 글자 위 = 패널 안쪽 위 | --space-5 |
| 목록 줄 | 상태 표시 높이 = 한 줄 높이 | 첫 줄 맞춤 |
```

세 파일이 아직 없거나 한 파일에 섞여 있으면, audit 첫 단계에서 네 층으로 나눈 **초안**을 만들어 보인다(내용은 그대로, 숫자는 토큰 이름으로, 토큰에 없는 숫자는 의심 목록으로). 사용자 승인 뒤에 나눈다.

## 모드

### audit — 전체 점검 (사용자가 부름)
1. **읽기**: 디자인 스펙 네 층, 모든 영역 spec의 `## 화면`, 코드의 스타일 · 부품.
2. **캡처와 측정**: 앱을 화면 기준 크기로 띄워 화면마다(빈 상태 · 많은 항목 · 가장 긴 실제 내용 포함) 캡처하고 자리 표의 관계를 잰다. 측정 방법은 그 프로젝트 plan의 "화면 측정 명령"을 쓴다. 캡처는 직접 열어 본다.
3. **용도 점검**: 화면마다 요소를 용도로 적는다. 표로 보인다.
   - 용도가 하나로 정해지는 요소: 그 용도가 정한 부품 · 크기와 같은지
   - 같은 일을 하는데 다른 용도 · 다른 부품으로 그려진 요소: 합칠 후보
   - 어느 용도에도 속하지 않는 요소: 새 용도 후보 또는 기존 용도로 옮길 후보
4. **값 점검**: `scripts/scan.py <스타일 파일 · 시안 HTML 경로…>`로 토큰이 아닌 값과 같거나 가까운 토큰을 모은다. 스펙 문서에 숫자가 직접 쓰였는지도 본다.
5. **자리 비교**: 2단계에서 잰 값을 화면 패턴별로 나란히 놓는다(제목 · 네비게이션 · 주요 동작 · 첫 줄 위치 · 줄 높이 · 단 폭). 같은 용도인데 잰 값이 다른 칸을 표시한다.
6. **점검표 보고**: 아래 형식으로 보이고, 후보마다 AskUserQuestion으로 **합치기 / 그대로 두기(이유) / 나중에**를 받는다. 많으면 종류별로 묶어 묻는다.
7. **스펙 반영**: 정한 것을 네 층 파일(필요하면 영역 spec의 `## 화면`)에 적는다. 그대로 두기는 이유를 그 항목 옆에 한 줄 남긴다. 새 관계는 자리 표에 더한다.
8. **코드 어긋남 기록**: 스펙과 코드가 다른 곳을 `backlog.md`의 "디자인 일관성" 절에 적는다. 한 줄에 하나: `무엇이 바뀜 → 맞출 파일(들) · 근거(스펙 위치)`.

### change — 변경 점검 (flow 2단계가 기존 화면을 바꿀 때 부름)
- 바뀌는 화면과 같은 용도를 쓰는 다른 화면을 함께 고른다.
- 바꾸기 전 캡처와 바꾼 뒤(시안 또는 구현) 캡처를 나란히 놓고 audit 3 · 5단계를 그 화면들에만 한다.
- 점검표와 전/후 캡처를 함께 보이고 사용자 승인을 받는다. 승인 기록에 한 행을 더한다.

### mockup — 시안 점검 (mockup 스킬이 부름)
- 시안을 사용자에게 보이기 **전에** audit 3 · 4 · 5단계를 시안 HTML과 디자인 스펙으로 한다. 시안의 요소마다 `data-role="<용도 이름>"`을 달아 용도 점검에 쓴다.
- 점검표를 시안과 함께 보인다. 걸린 것은 시안을 고쳐 기존 용도로 맞추거나, 새 용도가 필요하면 "기존 용도로 안 되는 이유"를 적는다.
- 시안이 승인되면 mockup 4단계에서 네 층 파일에 옮긴다(이 스킬의 7 · 8단계 규칙대로).

## 점검표 형식
```
## 디자인 일관성 점검표 (<날짜> · <audit|change|mockup> · 대상)

### 용도 점검
| 화면 | 요소 | 지금 부품 · 크기 | 용도 | 그 용도의 부품 · 크기 | 제안 |

### 자리 비교 (잰 값)
| 화면 패턴 | 관계 | 화면 A | 화면 B | … | 기준 |
(다른 칸은 **굵게**)

### 토큰에 없는 값
| 위치 | 속성 | 값 | 가까운 토큰 | 제안 |

### 합칠 후보 — 토큰 · 부품 · 용도
| 대상들 | 같은 점 / 다른 점 | 제안 |

### 요약
걸린 것 N개 · 결정 필요 N개 · 캡처 위치
```

## 지키는 범위
- 앱 코드는 읽고, 화면은 캡처해 잰다. 코드를 맞추는 일은 영역 작업이 한다.
- 토큰 · 부품 · 용도를 합치거나 값을 바꾸는 일은 사용자 결정대로 한다.
- 이 스킬에는 어느 프로젝트에나 맞는 규칙만 둔다. 특정 화면 이름 · 특정 값은 그 프로젝트의 디자인 스펙 파일에 둔다.
- 보고는 늘 점검표(와 캡처 위치)로 한다.
